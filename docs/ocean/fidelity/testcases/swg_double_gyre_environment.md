# SWG double-gyre reference environment

The bit-identical NEMO-versus-legoESM result was obtained with this reference
environment. The machine-readable counterpart is
`swg_double_gyre_environment.json`; the portable NEMO architecture template is
`scripts/data/nemo_swg_double_gyre/arch-conda-scalarmath.fcm.in`.

| Component | Reference value |
|---|---|
| NEMO | 5.0.2, source revision `dcc7fb8c1779fa8409e41e4ce3ab7d45b9ceb796` |
| Fortran | GNU Fortran 15.2.0, conda-forge `gcc 15.2.0-19` |
| MPI | Open MPI 5.0.10 |
| NEMO composition | no XIOS; `cpp -Dkey_nosignedzero`; scalar-math FCFLAGS in the JSON and reference arch; CFLAGS `-O0` |
| Python | 3.13.0 |
| Python packages | JAX 0.10.0, jaxlib 0.10.0, CUDA 12 plugin 0.10.0, NumPy 2.4.4, Equinox 0.13.7, imageio-ffmpeg 0.6.0 |
| GPU | Tesla V100S-PCIE-32GB, driver 580.126.20 |
| CPU | Intel Xeon Gold 6242R |
| OS | Linux 5.14.0-611.36.1.el9_7.x86_64 |

On 2026-10-13, the source revision, Fortran and MPI versions, Python stack,
CPU, and kernel were re-read from the mounted reference system with `git
rev-parse HEAD`, `gfortran --version`, `mpirun --version`, Python package
metadata, `/proc/cpuinfo`, and `uname -r`. The sandbox had no GPU; the GPU and
driver values are the operator's same-day measurement. The mounted NEMO source
checkout had local instrumentation, so the revision identifies the upstream
source state while the build manifest generated by `build_swg_dg.sh` pins the
actual binary, architecture, and case sources used by each colleague.

Exact floating-point identity is conditional on the complete environment,
not just the NEMO source revision. Always retain the generated build and run
manifests with comparison reports.
